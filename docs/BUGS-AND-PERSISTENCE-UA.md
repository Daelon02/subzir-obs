# SubZir v0.8.0 — можливі баги збереження та перевірки для гравця

Початковий перелік нижче описує опубліковану v0.8.0. Виправлення перевірено окремо в локальній збірці на ізольованих профілях Windows.

## Результат перевірки локальної збірки

| Сценарій | Результат |
|---|---|
| Дві зони → одна область → перезапуск → знову редактор | Відновилася одна активна область, а редактор відкрив обидві попередні зони. Після повторного збереження та перезапуску активувалася багатозонна розкладка. Скасована правка робочої копії не змінила збережений профіль. |
| Одна пошкоджена зона серед справних або прив’язка `99` | Справні зони залишилися в початковому порядку. Невідома прив’язка стала вільною. У папці `runtime` збережено побайтову копію оригіналу `zones-original-….json`. Основний файл однаково читають редактор і рушій. При повністю непридатному файлі програма показує повідомлення й зберігає оригінал до явного запису нової розкладки. |
| Заблокований або пошкоджений `area.txt` | Запис заблокованого файлу завершився помилкою, активний режим і старі байти збереглися. Після підстановки нульової ширини наступний запуск завантажив попередню придатну область із `area.previous.txt`. Без неї програма використовує придатні зони або пропонує вибрати область. |
| Локальне оновлення поверх копії v0.8.0 | Перевірено незмінність файлів профілю та тестового файлу моделі. Після оновлення програма прочитала мову інтерфейсу, мову перекладу, модель 7B, стислий режим, колір контуру й обидві зони. Для цієї перевірки використано файл-маркер моделі. |
| OCR при миттєвій зміні двох реплік | Той самий запис до виправлення давав `lei c` замість `Meet me at the station.`. Після виправлення Windows OCR через штатний режим зон підтвердив повну репліку. На окремому записі Люсії підтверджено спочатку верхній текст, потім обидва рядки з тьмяним продовженням. У цих двох перевірках після OCR використовувався тестовий перекладач. |

## Що варто перевірити першим

| Випадок | Що видно з коду v0.8.0 | Як перевірити та що вважати проблемою |
|---|---|---|
| Після вибору однієї області зникає багатозонна розкладка | Підтвердження вибору однієї області записує `runtime/area.txt` і видаляє `runtime/zones.json`. Це реалізований спосіб перемкнути режим. Окремої копії попередньої розкладки цей обробник не створює. | На тестовому профілі зберегти діалог і завдання як дві зони, перейти на одну область і знову відкрити редактор зон. Перевірити, чи гравцеві заздалегідь зрозуміло, що обидві позиції доведеться налаштовувати знову. Окремий дефект — якщо розкладка зникає навіть після скасування вибору. |
| Після перезапуску зникають усі зони через одну некоректну | Завантажувач приймає розкладку лише тоді, коли перевірку проходять усі зони. Якщо JSON читається, але одна зона має неприйнятні розміри, розкладка не активується. У цій гілці повідомлення немає. Сам файл на цьому кроці залишається на диску. | Лише в копії профілю змінити ширину однієї з двох зон на `0` і відкрити програму. Зафіксувати, що бачить гравець і чи пояснює інтерфейс причину. Окремо перевірити, чи можна відновити початковий файл до збереження нової розкладки. |
| Редактор показує «Вільна позиція», але переклад прив’язаний до оригіналу | Перевірка зони не перевіряє допустимі значення `Anchor`. Для невідомого числового значення редактор показує перший пункт списку, тоді як рендерер вважає будь-яке значення, крім `Manual`, прив’язкою. Це можлива неузгодженість для зміненого чи пошкодженого профілю. | У копії чинного `zones.json` встановити для звичайної зони `Anchor: 99`. Порівняти значення списку з позицією напису в попередньому перегляді та OBS. Вони мають відповідати одному режиму. |
| Перерване збереження однієї області | `area.txt` пишеться прямо в кінцевий файл. Для мов, вигляду й багатозонної розкладки використано тимчасовий файл із подальшою заміною. Тому перерваний запис області — окремий ризик. | На тестовій копії підставити порожній або частково записаний `area.txt` і перевірити відновлення після запуску. Це імітація наслідку. Вона не доводить, що звичайне закриття SubZir пошкоджує файл. |

Джерела для розбору цих випадків: [вибір однієї області](../launcher/Launcher.cs), [завантаження та збереження зон](../launcher/Zones.cs), [перевірка зони, редактор і розташування напису](../launcher/ZoneEditor.cs), [запис JSON-налаштувань](../launcher/Ui.cs).

## Що має переживати перезапуск

Перед перевіркою достатньо записати вибрані значення або зробити скріншот. Сценарії з ручною зміною файлів призначені для копії профілю.

| Що перевіряємо | Дії | Очікуваний результат |
|---|---|---|
| Мова інтерфейсу, мова перекладу й модель | Вибрати різні мови для кнопок і субтитрів, вибрати доступну сумісну модель, підтвердити й перезапустити. | Відновлюються всі три значення з `runtime/languages.json`. Зміна лише мови інтерфейсу зберігає попередню мову субтитрів. Якщо файл моделі зник, окремо зафіксувати вибір резервної моделі. |
| Стислий режим | Для 7B та українського перекладу ввімкнути стислий режим. Перезапустити, тимчасово перейти на іншу модель й повернутися на 7B. | Збережена перевага `dialogueStyle` знову застосовується на сумісній комбінації. Тимчасово недоступний перемикач сам по собі не означає втрату налаштування. |
| Вигляд і колір контуру | Вибрати помітний колір контуру, змінити розмір шрифту, натиснути «Застосувати». Після перезапуску порівняти діалог вигляду, попередній перегляд зони й OBS. Повторити з іншим кольором, цього разу натиснути «Скасувати». | Після застосування значення відновлюються з `runtime/subtitle-style.json`; після скасування залишається попередній колір. Старий профіль без `outline_color` отримує чорний контур. |
| Координати та режими кількох зон | Для діалогу вибрати «Над оригіналом», для завдання — «Під оригіналом», третю зону зробити легендою. Зберегти, перезапустити й відкрити той самий кадр. Потім пересунути зону та закрити редактор без збереження. | Збігаються кількість і порядок зон, рамки зчитування, ширина, прив’язки та режим легенди. Скасоване переміщення не змінює ані файл, ані розташування під час наступного перекладу. |
| Оновлення поверх наявної версії | Зберегти налаштований тестовий профіль і перелік моделей. Після оновлення порівняти файли налаштувань, а потім відкрити редактор та сцену OBS. | Моделі й налаштування залишаються доступними. Однаковий вміст файлу ще не доводить, що нова версія правильно читає його значення. |

## Що може залишитися на диску або зникнути навмисно

- **Відеофайл для перевірки.** Редактор записує зони на диск, а шлях до вибраного відео тримає в пам’яті поточного сеансу. Після перезапуску файл для повтору потрібно вибрати знову. Окремо варто перевірити, чи гравцеві зрозуміло, яке джерело буде використане після запуску.
- **Останній напис та службові зображення.** `caption.txt`, `ack.txt` і `zones-0.png` / `zones-1.png` використовуються для обміну з OBS. Перевірка для гравця — зупинити переклад на видимій фразі, перезапустити OBS і подивитися, чи не повернувся старий напис. Наявність службового PNG у папці сама по собі не є багом.
- **Контекст діалогу.** Попередні репліки зберігаються в пам’яті сеансу. Після нового запуску перекладу перша фраза не повинна успадковувати зміст попередньої розмови.

## Як записати знайдений баг

Вказати версію SubZir, мову інтерфейсу й субтитрів, модель, джерело гри та режим зон. Додати послідовність дій, значення до й після, очікуваний результат і те, що фактично показали SubZir та OBS. Для помилок збереження найкорисніша деталь — **коли саме зникла зміна**: одразу після «Застосувати», після повторного відкриття редактора, після перезапуску чи після оновлення.
